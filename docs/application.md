# Application

Last reviewed: 2026-11-11.

This file is the current description of the local ICEYE open-data viewer. Read it before changing a feature or deciding what the page may say. Update it in the same change when behavior, routes, constraints, or planned work change. Keep the claims as careful as the code.

`README.md` stays the checkout and run sheet. This file is the memory: what the application is for, how it is put together, what each feature does, how to work on it, and what is still ahead.

## Objectives

Show ICEYE synthetic-aperture radar scenes on a local page. A person can search the public open-data collection, download a scene onto this machine, and run measurements that stay inside what the rasters support.

The process still boots from one public collect, `ICEYE_EYCKP5_20251024T135309Z_6724574_X52_SLF` (ICEYE-X52, spotlight, X-band, VV, 24 October 2025, 13:53 UTC). Its footprint covers the 25 de Abril bridge. The radar files are not in git. They are fetched into `data/`. Other open-data scenes can sit beside it under `data/scenes/`. `scene.serve` copies a labeled placeholder of that collect when the Lisbon scene folder is missing or empty, then listens. A folder that already has `stac.json`, or any other file, is left as it is. Startup still exits when that `stac.json` is missing. If the record is removed and the folder is empty again, the next start seeds.

The page may state:

- STAC fields for the open scene (time, platform, mode, band, polarizations, orbit, incidence, footprint).
- The quicklook, thumbnail, and dwell video already on disk. The quicklook is shown in the product's own pixel orientation, downsampled so the long edge is at most 1600 pixels.
- Numbers and pictures produced by the measurement tools. Each picture carries its legend. Each briefing carries that tool's limit sentence.
- On an empty data directory, a drawn placeholder of the test scene. The banner, the picture, and the briefing say the numbers were not measured from an ICEYE raster. Those pictures are not a radar product.
- The person-written note in `content/scene_note.md`, and only on the fallback Python page. The React page does not show that note.

A bright mark is a bright radar return. The page does not name a ship, match AIS, fuse another sensor, or claim that a model read the radar. `python -m scene.analyze` calls `gpt-4o-mini` only when `OPENAI_API_KEY` is set, and that call may only phrase `measurements.json`. The belt never calls a model.

The catalogue in use is the public ICEYE open-data STAC collection, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). The commercial ICAS catalog is not called. Python here is this reader, this job, and this page. One container runs that same process. This checkout does not run in Kubernetes. A later pod sketch is under Future work. There is no air-gapped deploy and no second service depending on this process.

## Architecture

One Python process serves the page and the API. The React app is a static build. Catalog indexing, one download, and one measurement each run as a background thread in that process. The belt and the Lisbon measurement share the measurement thread, so one blocks the other. There is no database. A scene is a folder of files.

```text
browser
  ScenePage (Vite/React build in frontend/dist)
        |
        |  HTTP on 127.0.0.1:8765
        v
  scene.serve  ->  scene.web.dispatch
        |
        +-- catalog search and item JSON     (scene.catalog, scene.places)
        +-- one download thread              (scene.downloads, scene.fetch)
        +-- library scan of data/scenes      (scene.library, scene.loader)
        +-- one measurement thread           (scene.jobs)
              +-- belt tool                  (scene.belt)
              +-- Lisbon-only job            (scene.analyze)
              +-- scene report               (scene.report)
        +-- placeholder seed and clear       (scene.demo)
```

`docker compose up --build` builds one image and publishes port 8765. The image holds Python 3.12, curl, the package, `content/`, and `frontend/dist`. Node 26.13.0 builds the page. The image does not hold radar files, `intelligence/`, `.env`, or `OPENAI_API_KEY`. Compose passes that key from the shell or from a gitignored `.env` beside `docker-compose.yml` when one is set. An empty value counts as unset. A named volume is mounted at `/app/data`. `SCENE_HOST` is `0.0.0.0` inside the container. Before it listens, `scene.serve` calls `seed_if_needed`. The seed is generated by `demo/build_seed.py` into `demo/seed` during the image build, then copied into the volume. It is not baked into `/app/data`, because the volume mount would hide it.

Startup loads the Lisbon STAC item, the scene note, the fallback static files, and the Lisbon quicklook when `qlk-cog.tif` is present. `GET /` then serves `frontend/dist/index.html` when that file exists. When the build is missing, the same route serves the original Python page: the quicklook, the STAC fields, and `content/scene_note.md`.

### On disk

A scene id is one path segment, `[A-Za-z0-9_-]+`. `scene.paths.scene_dir` refuses anything else, and the HTTP routes use the same check. The server never serves `data/` by a caller-supplied path.

```text
data/scenes/<scene-id>/
  stac.json
  {asset-key}{suffix}     qlk-cog.tif, graphic.png, grd-cog.tif, grd-json.json, vid-cog.tif
  analysis/<tool-id>/
    overview.png
    measurements.json
    briefing.md
  analysis/amplitude-change/<partner-id>/
    overview.png
    measurements.json
    briefing.md
  report/report.json        phase, tool order, the lead, and one section per included tool
```

Asset filenames are `{stac-key}{suffix from the href}`, from `scene.naming`. Fetch, the loader, and downloads share that rule. `qlk-cog.tif` and `graphic.png` are the names this checkout uses. A flat `data/stac.json` checkout, from the first Lisbon download, is moved into `data/scenes/<id>/` on startup (`scene.store`). The move is a rename on the same filesystem.

Single-scene tools, motion, and stack tools write under `analysis/<tool-id>/`. Only amplitude change adds the partner scene id as another directory. A stack still compares every matched scene. It stores one result on the scene that was open, with `partner_id` null.

The Lisbon script is separate. It writes `intelligence/measurements.json`, `intelligence/returns.geojson`, `intelligence/overview.png`, and `intelligence/briefing.md`, and it reads only the Lisbon test scene.

### What a measurement reads

Belt tools do not read the full raster. `scene.belt.raster` takes the COG overview whose long side is at most about 1600 pixels for a GRD, and about 1200 for a dwell stack. Sigma-nought is `calibration_factor * DN^2`, in decibels. The factor is read from `grd-json.json` (`iceye:calibration_factor`, `sar:calibration_factor`, or `calibration_factor`). The Lisbon scene has a hardcoded factor when that sidecar omits it. Areas use the ground size of those overview pixels, from `proj:transform` in the same sidecar.

`grd-json.json` is not part of the preview pack. A tool that looks runnable still fails at read time when the sidecar is missing. The dwell video on the stage is `vid-mp4`. Dwell motion reads `vid-cog.tif`, the georeferenced stack.

### HTTP

The server is `ThreadingHTTPServer` from the standard library. It binds `127.0.0.1:8765` unless `SCENE_HOST` and `SCENE_PORT` say otherwise. It answers GET, POST, and HEAD. Catalog thumbnails are proxied only after the URL is HTTPS on `iceye-open-data-catalog.s3.amazonaws.com` or `iceye-open-data-catalog.s3-us-west-2.amazonaws.com`.

| Method and path | What it does |
| --- | --- |
| `GET /` | React app, or the fallback Python page. |
| `GET /api/scene` | Original Lisbon contract. Always attaches `intelligence/` when those files exist. The React page does not call it. |
| `GET /api/library` | Scenes whose `stac.json` this reader accepts. Broken folders are skipped. |
| `GET /api/scenes/<id>` | One scene on disk. The `intelligence/` measurement is attached only for the test scene. The stage does not draw `/overview.png`. |
| `GET /api/scenes/<id>/quicklook.png` | `qlk-cog.tif` rendered to a grayscale PNG, long edge at most 1600, cached by file mtime. The `graphic` file is served when the quicklook is absent. |
| `GET /api/scenes/<id>/thumbnail` | The local `graphic` file. |
| `GET /api/scenes/<id>/video` | The local `vid-mp4` file, as `video/mp4`. |
| `GET /api/scenes/<id>/tools` | Every belt tool, with its lock sentence, pair partners, an overview URL, and the saved summary and briefing when those files are on disk. |
| `POST /api/demo/clear` | Remove placeholder pictures, analysis files, and `demo.json`. The STAC record stays. Body must be empty. 404 when no scene is marked as a placeholder. |
| `POST /api/scenes/<id>/report/run` | Start the report. Body: `partner_id` null, or one scene id. The code chooses the tools. 400 when `partner_id` is missing or not a scene id (`partner_id must be null or one scene id`), when the partner is not eligible (`partner_id is not a scene this report can compare.`), or when nothing can run (`No tool can run for this scene.`). 409 with `Set OPENAI_API_KEY to ask a question.` when the key is unset. A second measurement returns 409 with `{"status": "running"}`. |
| `GET /api/scenes/<id>/report` | The saved report, partial while a job runs. Fields: `question` (empty for a new run), `partner_id`, `phase` (`planning`, `running`, `writing`, `done`), `tool_order`, `synthesis_md`, `synthesis_source` (`model` or `belt`), and `sections`. Each section has `progress_note`. An empty `sections` list when none was saved. |
| `GET /api/scenes/<id>/report.pdf` | The saved report as a WeasyPrint PDF. 404 when none was saved. 500 with `The report PDF could not be written.` when the writer fails. The route does not call the model. |
| `GET /api/report/key` | Whether this process has an OpenAI key. Body: `configured` and `source` (`unset`, `environment`, or `session`). The key is not returned. |
| `POST /api/report/key` | Keep a key for this process only. Body: `api_key`. Nothing is written to disk. 409 when a key already arrived from the environment. 400 when the key is empty, contains spaces, or is longer than 512 characters. The response is the same status object as the GET, and it does not echo the key. |
| `POST /api/jobs/run` | Start one belt tool. Body: `scene_id`, `tool_id`, optional `partner_id`. |
| `POST /api/jobs/measure` | Start the Lisbon-only measurement. Body must be empty. Same thread as `/api/jobs/run`. |
| `GET /api/jobs/current` | That single job: idle, running, done, or failed, plus the step sentence and, when done, the measurement and briefing HTML. |
| `GET /api/scenes/<id>/analysis/<tool>/overview.png` | A belt picture. Amplitude change inserts `/<partner>` before `overview.png`. |
| `GET /overview.png` | `intelligence/overview.png` for the Lisbon job. |
| `GET /quicklook.png` | Rendered quicklook of the Lisbon scene loaded at startup. |
| `GET /static/scene.css`, `GET /static/scene.js` | Fallback page assets, loaded into memory at startup. |
| `GET /api/catalog/search` | Filter the cached collection. See Catalog below. |
| `POST /api/catalog/refresh` | Delete `data/catalog-index.json` and read the collection again. Body empty. |
| `GET /api/catalog/items/<id>` | One item and its asset list. URLs stay on the server. Asset sizes come from HEAD requests. |
| `GET /api/catalog/items/<id>/thumbnail` | Proxied catalog thumbnail. |
| `POST /api/downloads` | Start one download. Body: `item_id`, and `assets` as a list of keys. Omit `assets` for the preview pack. |
| `GET /api/downloads/current` | The single download and a byte count per file. |
| `POST /client-error` | Browser `error` and `unhandledrejection` events. Logged, not stored. Returns 204. |

A second measurement or a second download returns 409. A report run is a measurement, so it shares that lock with the belt and the Lisbon job. Unknown paths return a short plain-text error. POST requires `Content-Length`, except `/api/jobs/measure`, `/api/catalog/refresh`, and `/api/demo/clear`, which may be empty. Bodies over 16 KiB are rejected, and a client-error body over 2 KiB is rejected.

Hashed files under `frontend/dist` are cached for a year. `index.html` is `no-store`.

### Frontend

`frontend/src/App.tsx` renders one `ScenePage`. The shell is a header, a tool column, a stage, one right-hand pane, and a download dock along the bottom. The header puts the radar mark and the name Open data on the left. The center is labeled Selected scene: "25 de Abril bridge" for the test scene and the scene id otherwise, then the collected time, platform, mode, band, and polarization. That facts line opens the metadata card. The card starts closed. The tool column lists Scene (Preview, Catalog, Library, Report), then the measurement groups. A group is a disclosure with a chevron, not a tool. Groups stay collapsed until opened, and the group that holds the selected tool stays open. Each measurement has its own icon. A locked tool stays clickable and shows a lock; the pane still names the missing file. The pane starts closed. On a narrow viewport the column scrolls sideways and the pane stacks under the stage. Choosing the open tool, Close, or Escape shuts the pane. Escape is ignored while focus is in a field. Opening a scene from the catalog or the library closes the pane.

The stage shows the quicklook, thumbnail, or dwell video. A belt picture replaces that preview only when the selected tool produced it and the URL contains `/analysis/<that-tool>/`. The Lisbon `/overview.png` is not that picture.

The React page loads the library, then opens the test scene, or the first library row when the test scene is absent. It polls a running download and a running measurement every 400 ms. While the catalog index is still filling, the catalog pane polls every 2 seconds. When the open scene has `demo.json`, a banner under the header repeats the placeholder sentence and offers Clear demo data. That button calls `POST /api/demo/clear` and reloads the scene. It does not run on the first click anywhere else.

UI kit: React 19, Vite, Tailwind 4, Base UI, and the local `components/ui` primitives. Icons are Lucide. The default theme is dark. Imports inside `frontend/src` use the `@/` alias.

### Two measurement paths

The belt (`scene.belt`) is the path the tool column runs. It works for any scene on disk whose files and geometry the tool accepts. Output stays in that scene's `analysis/` folder. The briefing is markdown rendered from the summary rows and the limit sentence. The belt does not call a model. Only the scene report, below, does, and it keeps the belt briefing as its fallback.

`scene.analyze` is the older Lisbon job. It needs the GRD and the dwell stack for the 25 de Abril collect, optionally reads the colorized sub-aperture image as a second vote, and records the SLC sidecar without detecting on it. `POST /api/jobs/measure` still starts it. `ResultsSection` and `use-measure-job` are still in `frontend/src/scene` and are not mounted by `ScenePage`. `fetchScene` (`GET /api/scene`) is also unused by the page. It remains covered by `frontend/src/api.test.ts`.

## Features

### Preview

Opens the scene on the stage. The caption switches among quicklook, thumbnail, and dwell video, and names the collected time. A choice is disabled when that file is not on disk. The caption hides those choices while an analysis picture is on the stage. The Preview pane holds the description. The quicklook stays in product orientation. It is not a map and not a detection layer. While the library is still loading and no scene is open, the stage says it is opening the library. With no scene open after that, the stage asks for a library scene. With a scene and no quicklook, it asks for the preview pack.

### Catalog

Searches the static open-data collection at `https://iceye-open-data-catalog.s3.amazonaws.com/collections/iceye-sar.json`. There is no account and no STAC API. The collection document is a list of item links.

The first search reads that list. The scene id is the link title, or the href stem when the title is missing. Date, satellite, and product code are parsed from an id that matches the ICEYE pattern, so those filters work before any item JSON arrives. Other ids still list, with those three fields empty. Item JSON then fills footprint, mode, incidence, orbit, look side, thumbnail, and assets. A background pool of four workers does that, the visible page first, and the result is cached in `data/catalog-index.json` for 24 hours. An item that fails twice is skipped until Refresh, or until the process starts again. Refresh deletes the cache file and reads the collection again.

The text box is a case-insensitive substring of the scene id. It does not search place, mode, or satellite. The other filters are start and end date, satellite, product code, and a west,south,east,north bbox. The client sends a bbox only when all four edges are numbers. The server rejects a bbox that is unordered or has the wrong number of edges. The page size is 24, and the server clamps `limit` to 1–100.

A bbox is applied only to items whose footprint is already cached. `unread_for_bbox` counts matches of the other filters that still have no footprint, so an empty page during indexing is not a finished answer. The pane shows that status while `indexing` is true.

Each cached row is labeled with the nearest place within 150 km of the footprint centre, from `places.json`. Farther than that, the label is "Open sea". The catalogue has no place field of its own. A row that is not cached yet has no place.

Clicking a row opens its asset checklist in the pane. It does not open the scene. Open is shown only when that scene is already on disk. It opens that scene on the stage and closes the pane. Download starts the one download job.

The default selection is the preview pack: `graphic`, `qlk-cog`, `qlk-json`, and `vid-mp4` when the item has it. The STAC item is always written as `stac.json`, whether or not it was checked. Large products stay unchecked until someone selects them. The named large keys are `grd-cog`, `csi-cog`, `vid-cog`, `slc-cog`, `cphd`, `sicd`, and `sidd`. Any other asset whose STAC role includes `data` is also treated as large. For the Lisbon test scene the big rasters are about 484 MB (GRD), 1.2 GB (colorized sub-aperture), 827 MB (dwell stack), and 11 GB (SLC).

### Downloads

One download at a time. Progress is the size of the file curl is writing. curl resumes a partial file, and a file that already matches the remote size is kept (`kept` in the file list). A failed file leaves earlier files in the scene folder. The dock lists each file and its byte count, and it hides while the download is idle. The dock leads with the job sentence and keeps the scene id on the second line. Open is shown when that scene is not the one on stage. It opens the scene and leaves the dock up. When the download finishes, the library reloads. Dismiss only clears the dock. If that scene folder still has `demo.json`, a finished download deletes the placeholder analysis and any drawn picture it did not replace. `python -m scene.fetch` does the same after its assets are on disk. A failed download leaves `demo.json` and the drawn files in place.

### Library

Lists `data/scenes/*/stac.json`. There is no second index. The Lisbon collect is marked as the test scene and sorted first. A folder with `demo.json` is also marked Demo data. The rest follow `collected_at`, newest first. Choosing a row opens it on the stage and closes the pane. Refresh rescans the folders. An empty library points at the catalog.

### Demo placeholder

An empty data directory is not an empty page. `scene.demo` draws a gray frame, writes a small TIFF quicklook and a PNG thumbnail, and writes `measurements.json` and `briefing.md` for open water, sea roughness, built-up, returns on water, and long structure. The summary values are round and labeled placeholder. The limit sentence says they were not computed from a raster. Motion, change, and stack have no picture. There is no `grd-cog.tif`, so every tool stays locked and Run cannot overwrite the files. The lock sentence starts with the same note.

`demo.json` in the scene folder is the marker. The library badge and the banner both read it. Clear demo data deletes `demo.json`, the drawn pictures, and `analysis/`, and leaves `stac.json`. The next start does not copy the pictures back while that record is there. The times and the footprint in the placeholder record are the public values for this collect. After Clear, the banner is gone and those fields are what the page still shows. If the record is removed and the folder is empty, the next start seeds again. A Lisbon folder that already holds rasters and has no `stac.json` is not overwritten. Clearing does not delete any other scene.

### Facts

The compact set — collected time, platform, mode, band, and polarization — is the facts line under Selected scene, in the center of the header. Choosing that line opens the card on the picture. Hide closes it. The card starts closed. All fields adds the scene id, the acquisition window, orbit, incidence to one decimal, and the bounding box to three decimals.

### Analysis belt

The tool column groups the measurements as Surface, Objects, Motion, Change, and Stack. `GET /api/scenes/<id>/tools` decides which ones can run. A tool the scene cannot support stays in the list and names the missing file or the missing second look. The page uses the belt names.

Running a tool draws a decibel picture with the legend in the PNG, then writes `measurements.json` and `briefing.md`. The pane shows the step sentence, then the summary rows and the briefing HTML from that job. Selecting a tool that already has those files puts the picture, the summary, and the briefing back without another run. A finished job in this session replaces that saved view until another tool is selected.

Single-scene tools need `grd-cog.tif` and a calibration factor, and they run on spotlight and stripmap. Any other mode, including Scan and Scan Wide, stays locked because those GRDs are not treated as radiometrically calibrated. Dwell motion also needs `vid-cog.tif`.

Change and stack tools compare scenes that share a look: same orbit direction, same look side, incidence within 1 degree, and footprints that overlap by at least 30 percent of the smaller one. The 1 degree window is there because X-band VV sea sigma-nought can fall by about a decibel per degree of incidence between 26° and 34°. Both scenes need a calibrated GRD on disk. Partner scenes are resampled onto the open scene's overview grid. Outside the footprint the sample is empty. A pair tool asks for one partner. A stack tool uses every match and says how many. The stack mean stays locked until five matched scenes, including the open one, are on disk.

| Tool | What it reports |
| --- | --- |
| Open water | Dark smooth water, from the darkest histogram mode. Area, fraction of the scene, and median sigma-nought. Shadow, tarmac, and sand are dark for the same reason. Flooded vegetation and flooded streets get brighter, so this mask marks them dry. |
| Sea roughness | Calm water against wind-roughened water, inside the water mask. A sea that spans less than 1.5 dB stays one class. This is roughness, not a wave period, a wave height, or a current. |
| Built-up return | Bright clusters on land. Fraction of land and a cluster count. Brightness is a double-bounce return, not a building height and not a land-use class. |
| Returns on water | Compact bright returns that touch the water. The label stays bright return. A hull, a pier, and a platform all qualify. |
| Long structure | A long bright return along the waterline. The length is the end-to-end extent of the bright return, layover included. An empty class is a valid result. |
| Dwell motion | Tracks of bright returns during this collect. Cyan held still. Red moved. Displacement and speed over those seconds, not a route. |
| Amplitude change | Earlier date in red, later date in cyan. The picture is that shared stretch, so a difference under 3 dB, or a patch under 8 pixels, still takes colour. Gray is where the two dates match. The darker, brighter, and unchanged areas count a difference of at least 3 dB in a patch of at least 8 pixels. It does not name a flood or a vessel. |
| Water persistence | How many dates each pixel is water. Two dates are a pair, not a seasonal record. |
| Sea state | Median sigma-nought of the water on each date. A lower bar is a darker sea, not a Beaufort number. |
| Dark sea anomaly | Water at least 2 dB darker than the stack median, in a patch of at least 8 pixels, whose surrounding ring is at least 1 dB brighter. Extent only. The title stays dark sea anomaly. |
| Shoreline | The waterline once per date. A shift is a waterline, not a tide height. |
| Date of change | The date a pixel left the stack median, when the departure is at least 3 dB and the patch is at least 8 pixels. |
| Repeat returns | A bright return seen on many dates against one seen once. Many dates can be a rock, a pier, or a moored hull. |
| Site activity | A bright cluster that appears or leaves relative to the stack median. |
| Stack mean | The mean of at least five matched dates. Averaging cuts speckle where the surface was stable. A surface that changed is blurred, not removed. |

### Scene report

**Start** writes one report for the open scene. The page does not ask for a question. The code chooses the tools. The model only orders that set, writes one short line while each tool runs, and then writes the lead. The file is `data/scenes/<id>/report/report.json`. The routes that remain are in the HTTP table above. `POST .../report/plan` and `POST .../report/amplitude` are gone. The PDF is that saved file, rendered as HTML and written with WeasyPrint. The PDF route does not call the model.

On the page, Report replaces the picture. The opening text says what Start will measure and what it will not claim. A bright return stays a bright radar return. The prose may not name a ship, a spill, a tide height, or a building height. A scene that is only in the catalogue is not downloaded. The person may leave the second-scene choice as this scene only, or pick one partner from the amplitude-change list. That list is the unlocked partners already on disk with the same look. No eligible partner hides the picker. **Start** posts `{ "partner_id": null }` or one scene id. The body has no question and no tool ids. If nothing can run, the route answers 400 and does not start a job. The page shows that sentence. The side pane is titled **This report**. While the job runs it lists Plan, each id in `tool_order`, then Write the report. The active row shows the narrator line. Finished sections appear in the document with their picture and summary as they save. A saved report stays on the page, and Start again replaces it. **Download PDF** requests `GET /api/scenes/<id>/report.pdf`.

When no key is set, the page asks for one and Start stays disabled. **Save key** keeps it in this process only. Restarting the container clears a key entered there. A key that arrived from the environment is used as it is, and the field stays hidden. **Use a different key** is offered only for a key entered on the page. Without a key the run route answers 409 with `Set OPENAI_API_KEY to ask a question.` and does not start a job.

The set is chosen in code, from the belt's lock state for the open scene:

- No second scene: every tool whose kind is single or motion. A locked one is a section with the belt's lock sentence and is not run. Change and stack tools are omitted, including their lock lines.
- A second scene: those same tools, amplitude change against that partner, and every stack tool, including a locked stack tool and a locked stack mean. A locked tool in that set is a section with the belt's lock sentence and is not run. A stack tool that does run compares every matched date, not only the picked partner, and the report says so.
- A partner the belt does not list, or a locked comparison, is a 400: `partner_id is not a scene this report can compare.` Nothing runnable does not start a job. That 400 begins `No tool can run for this scene.` Catalogue scenes are not fetched.

`question` stays in the file as an empty string. A new run also stores `partner_id`, `phase` (`planning`, `running`, `writing`, or `done`), `tool_order`, `synthesis_md`, and `synthesis_source` (`model` or `belt`). Each section has the tool id, a status, the tool's `measurements.json` when it ran, `briefing_md`, `briefing_source`, the picture URL, `partner_id` for an amplitude change, and `progress_note`. The status a new run writes is `done`, `locked`, `running`, or `failed`. An older file may still say `waiting`, and it still loads. A new run does not write `waiting`. The file is written while the order is being chosen, again when that order is known, after every section, while the lead is written, and after it. A missing newer key keeps a default, so an older `report.json` still loads.

**One thread.** The report runs on the same measurement thread as the belt. Ordering happens there, so the page does not call a plan route. Tools run one at a time, in the order the model gave when that order is a permutation of the runnable ids. Otherwise the order is the belt catalog. A tool whose folder already has `measurements.json` is not measured again. Amplitude change reuses a result only for the same partner directory. A tool that raises becomes a `failed` section with a one-line reason, and the next tool still runs. A locked tool is not run. Starting a report while any measurement is running is a 409 with `{"status": "running"}`. A second run for the same scene replaces `report.json`. The files under `analysis/` stay.

The model is `gpt-4o-mini`. None of the three calls receives a raster, a quicklook, or an overview image. A call that fails does not stop the run.

1. **Order.** Temperature 0. The reply must use each runnable id once. A bad or failed reply falls back to belt catalog order.
2. **Narrator.** Temperature 0.7, once before each tool runs. One or two sentences about the work that tool is doing, and it names the scene mode. It does not invent a target and it does not state a measurement. A failed or blank call stores a plain sentence and the tool still runs. That line is the job sentence and the section `progress_note`, so the 400 ms poll can show it while the raster runs. It is not copied into the finished document or the PDF.
3. **Synthesis.** Temperature 0, once, after the last tool. It receives the scene facts, the partner, every summary, every limit, the failures, the lock reasons, and `content/sar_glossary.md`. That file is the only extra wording it may use. It writes a lead that states the numbers, a hedged reading of what they support, and what may have gone wrong: a limit that applies, a failed tool, or a stack of only two dates. A jargon word is paired with a plain hint in the same sentence. A failed or blank call stores a lead built from the summary rows and the limits, marked `belt`. When a stack tool ran, that lead keeps the sentence that every matched date was compared.

**What the model may not claim.** A bright return stays a bright radar return. The prose may not name a ship, a spill, a tide height, or a building height. The same limits are in the narrator prompt and the synthesis prompt. The code does not scan the lead for those words. A sentence that breaks them is kept, so the instructions lower the risk and do not rule it out. Each finished tool section keeps the belt's own `briefing.md` and its limit sentence. The model does not rewrite that section.

**PDF.** `src/scene/report/pdf.py` renders one HTML document: inline CSS, A4, a page header, page numbers, a page break before each tool, and local `overview.png` paths. WeasyPrint writes the bytes. `fpdf2` is not a dependency. The image installs Pango, Cairo, GDK-Pixbuf, and a Liberation font. The tests build the HTML and mock the writer, so the suite does not need those libraries. A machine that generates a real PDF needs the same packages. A PDF that cannot be built is a 500 with `The report PDF could not be written.` The exception text goes to the server log only. A finished report job has `result: null` in `GET /api/jobs/current`, so belt panes never read it as tool output. The page loads the report after every start, even when the first job read is already done or failed.

### Fallback page and the Lisbon briefing

With no `frontend/dist/index.html`, `GET /` renders the Python page from `scene.page`. That page shows the quicklook, the STAC fields, which assets are on disk, and `content/scene_note.md`. It states that no detector has run. It has no question box.

`python -m scene.analyze` writes the Lisbon briefing. With `OPENAI_API_KEY` unset, the prose is rendered from `measurements.json`. With the key set, in the environment or in a gitignored `.env`, an existing environment value wins over `.env`. The request uses `gpt-4o-mini` at temperature 0. Raw DN values are removed before the call. The prompt may use only numbers present in the JSON, and it may not name a ship or a bridge.

### Troubleshooting

| What you see | What it means |
| --- | --- |
| `No module named scene` | The command used `python`, not `.venv/bin/python`. |
| Startup exits before it listens | The Lisbon `stac.json` is missing, `content/scene_note.md` is missing, or `src/scene/static/scene.css` or `scene.js` is missing. The message names the file. Run `.venv/bin/python -m scene.fetch` for the STAC item. |
| Startup exits while reading the quicklook | `qlk-cog.tif` is present and Pillow could not encode it. A missing quicklook does not stop startup. |
| `Could not listen on 127.0.0.1:8765` | That port is taken, or `SCENE_PORT` is not a valid port. |
| The page is the plain Python layout | `frontend/dist/index.html` is missing. Run `pnpm --dir frontend build`. |
| A tool is visible and will not run | Read its lock sentence. It names the missing raster, the missing calibration, or the missing second look. |
| The dwell video plays and Motion stays locked | The stage video is `vid-mp4`. Motion reads `vid-cog.tif`. |
| A tool starts and fails on the sidecar | `grd-json.json` is missing. The lock can pass for the Lisbon scene from the hardcoded calibration factor, then the run still needs the sidecar for `proj:transform`. |
| Change and stack stay locked with GRDs on disk | The other scenes do not share orbit, look side, and incidence within 1 degree, or the footprints overlap by less than 30 percent of the smaller one. Any mode other than spotlight or stripmap stays locked. |
| Catalog text finds nothing you can see in the row | The box matches the scene id only. Place and mode are not searched. |
| Catalog search is empty for a bbox | The index may still be reading item JSON. `unread_for_bbox` counts rows that passed the other filters and still have no footprint. |
| Download sits on one large file | curl is streaming it. The dock byte count is the file size on disk. One download runs at a time. |
| `POST /api/jobs/run`, `/api/jobs/measure`, or `/api/downloads` returns 409 | That kind of job is already running. The two measurement routes share one thread. |
| The picture is back and the numbers are not | The tool folder has `overview.png` and no `measurements.json`. A folder that has both reloads the summary and the briefing with the picture. |
| Lisbon measurement fails at once | `scene.analyze` requires `grd-cog.tif` and `vid-cog.tif` in the Lisbon scene folder. Fetch them with `--all`. |
| Browser error with no UI message | The page posts it to `/client-error`. The server log line is `browser error message=… source=…`. |
| A scene folder never appears in the library | It needs a `stac.json` this loader accepts, and a scene id that is a single safe path segment. A required STAC field of the wrong type drops the folder. |

### Kubernetes sketch

This checkout is one process with job state in memory and scenes on a local disk. That shape does not scale by adding replicas. Two pods with the current code would each keep their own measurement thread and would disagree about `data/` unless they share a volume.

A first pod is that same process, one replica:

- The image from `Dockerfile`. `SCENE_HOST=0.0.0.0`, container port 8765, a Service in front of it.
- A PersistentVolumeClaim mounted at `data/`. The catalog cache and scene folders live there. `ReadWriteOnce` is enough for one pod. An empty volume is seeded before the process listens. `intelligence/` is not in the image.
- The scene note and the static fallback files are in the image. After the seed, the Lisbon `stac.json` is on the volume. Without the seed and without that file, the pod is not ready.
- `OPENAI_API_KEY` comes from a Secret when the pipeline exists. The image does not contain it.
- No Ingress change is required for a local cluster. A later Ingress terminates TLS and leaves the pod speaking plain HTTP on 8765.

A grid of pods is a later split, and it needs a queue this repository does not have:

| Pod | Role |
| --- | --- |
| Web | The current server: the page, catalog search, library, and download. One replica until download progress also leaves this process. |
| Index | The catalog enricher, if it is lifted out of the web process. Writes `catalog-index.json` on the shared volume. |
| Measure | One belt run per pod. Reads scene folders, writes `analysis/`. The web pod records the job as running. The 409 lock moves from a thread to the queue. |
| Brief | Optional. Reads `measurements.json` only, writes the briefing. Same claim limits as `scene.analyze`. |

Measure pods need a shared filesystem (`ReadWriteMany`) or an object store in place of `data/scenes`. They do not need the React build. The web pod does not need scipy once measurement has moved. Until that split exists, run one pod. Horizontal pod autoscaling on the current server would multiply in-memory jobs and corrupt the single-download assumption.
